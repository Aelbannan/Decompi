# M1b parity — definition and deviation list

**Parity definition (SPEC §13.4):** golden-corpus comparison with a documented
deviation list. The M1b recorded-case fixtures (`tests/fixtures/parity-*`,
generated by `scripts/gen-parity-fixtures.py` from the REAL Xenoblade fork
Python tools) are the ground truth; `tests/parse-parity.test.ts` asserts the TS
ports reproduce them. Re-run the generator whenever recorded cases change and
commit the fixtures.

Reference tools (Xenoblade fork): `tools/coop/extc.py` (scan/plan),
`tools/coop/member_check.py`, `tools/symbolrecover/lib/parser.py`.

## Documented deviations

1. **Region merge scope (extc).** `extc.py._retail_tables` merges us + eu +
   retail_reloc_map names into one set; the TS `SymbolTable` is single-region.
   `classifyExternC`/`planMemberConversion` accept an optional
   `RelocMap` (`src/parse/symbols/reloc-map.ts`) to add reloc-map names; the
   parity fixtures are us-only (self-validated in the generator).
2. **`jp_stale` category vs Python's separate list.** Python reports
   `("exact", region)` + a separate `jp_stale` record; TS folds it into the
   `jp_stale` category (SPEC §13.3 `extc.jp_stale_address`). The guard matches
   Python's `any(rn == name)`: fires only when the declared name is NOT among
   the embedded address's occupants (`func_X`/`lbl_X` aliases never fire).
3. **objscan aligned-only (fix #8).** Python counts raw packed-byte
   occurrences at ANY byte offset; TS scans only 4-byte ALIGNED offsets (each
   hit carries its slot offset). Unaligned pointers are missed — proven by
   `parse-objscan` "unaligned pointers are NOT found". Real retail vtables are
   aligned, so this is theoretical.
4. **dtk drops out-of-function instructions (fix #10).** Python
   `_parse_file` keeps every instruction line, inside or outside `.fn`;
   `parseAsmFile` keeps only `.fn`-wrapped code. Real dtk dumps always wrap —
   proven by `parse-dtk` "drops instructions OUTSIDE .fn/.endfn".
5. **Tier C kind vs string (fix #9).** The ambiguous-provenance case is kind
   `undecidable` (SPEC §13.3 `member.tier_c -> undecidable`); `verdictString`
   carries the reference's EXACT string ("Tier B: flag for review (derefs r3;
   no instance-anchored call sites)"). The reference's own docstring defines
   the case as UNDECIDABLE; `header_drift`'s confident flags are unaffected.
6. **plan recipe mangling canonicalization.** Python `plan`'s `member_mangled`
   is naive (`name__<len>ClassFv`); for `__ct__`/`__dt__` declared names that
   is not a valid MWCC name. TS `MemberPlanTarget.mangled` is Python-verbatim
   parity; `canonical` is the MWCC-correct ctor/dtor/method target. Parity
   test asserts equality for methods and the documented difference for ct/dt.
7. **r3 provenance is FILE-GLOBAL (fix #6).** TS now back-scans the per-file
   instruction list (window i-1..i-9 can cross into the prior function) —
   true parity with `member_check.r3_provenance(idx.files[rel], i)`; this was
   a bug fix, not a deviation.
8. **`byName` first-wins / `byAddress` multi-valued (fixes #1/#7).** Python's
   `names` dict is `setdefault` (first wins) and `addr_hits` is a list of all
   occupants; TS mirrors both. `byAddress: Map<number, string[]>`.
9. **Anonymous-namespace qualifiers (fix #5).** `parseMangled` strips only the
   known dtk local suffixes (`@instance`, `@<digits>`) before qualifier
   parsing, so `__Q219@unnamed@CGame_cpp@12CGameRestartFv` parses as a scoped
   member (className `CGameRestart`). Python's `parse_qualifier_class` returns
   None for these (it is only used for display); TS is strictly more capable
   — not a parity regression.
10. **`member_candidates` hint axis (fix #2).** Python's `member_candidates`
    list records `bool(self_style)` per entry; TS exposes the same union
    (`'__' in name` OR self-style first param) as the independent
    `memberCandidateHint` on every classification result.
